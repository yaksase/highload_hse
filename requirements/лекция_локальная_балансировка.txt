Лекция 4. Локальная балансировка нагрузки
Внешний (входящий) трафик
• Приходит в ДЦ из глобальной балансировки на
определенные IP адреса.
• Обрабатывается на узле с данным IP либо
балансируется на набор других узлов одним из
способов.
Внутренний (межсервисный) трафик
• Может балансироваться тем же способом что и
внешний трафик.
• Может подаваться на тот же вход что и внешний
трафик для упрощения схемы балансировки.
• Есть дополнительные способы балансировки
доступные только для межсервисного трафика.

Локальная балансировка внутри ДЦ
Варианты реализации
• Один IP-адрес в ответе
• Все IP-адреса в ответе
Проблемы
1. Кеширование в ОС и приложении
2. Игнорирование TTL приложениями (пример: nginx)
3. Высокая нагрузка на DNS и дополнительная задержка в случае
нулевого TTL
4. Постоянные подключения могут балансироваться неравномерно
(балансировка только в момент подключения)
5. В общем случае нужна реализация клиентской балансировки с
DNS в качестве протокола service discovery

Политика failover
Алгоритм выбора другого (следующего) бекенда в случае отказа текущего в процессе
обработки запроса
На примере nginx:
proxy_next_upstream <список ситуаций>
proxy_next_upstream_timeout
proxy_next_upstream_tries

Прочие виды балансировки
Локальная балансировка внутри ДЦ
Redirect Based Load Balancing
▪Почти также дешев как DNS
▪Увеличивает задержку на каждый запрос
▪Имеет единую точку отказа
▪Хорош для выдачи ближайшего к пользователю сервера
Application Based Load Balancing
▪Выдаем в приложении прямые ссылки на сервера
▪Обеспечиваем балансировку и отказоустойчивость
▪При хорошей реализации одно из самых эффективных решений
Минусы:
▪Неудобно программировать
▪Раскрываем внутреннее устройство проекта
Client Based Load Balancing
▪Выбор сервера в коде страницы в браузере
▪Легко обеспечить отказоустойчивость запросив другой сервер
Минусы:
▪Плохо совместим с AJAX из-за crossdomain policy
Функциональное разделение
▪Уносим форум на отдельный домен
▪Уносим статику на отдельный домен
▪И так далее…
Минусы:
▪Сложно администрировать
▪Легко попасть на неделимый кусок сайта
