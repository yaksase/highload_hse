# Сценарий выступления на 5 минут

## 0:00-0:30 — Слайд 1. Тема
Открываю с формулировки проекта: это публичная AI-платформа уровня ChatGPT или Claude, у которой есть два канала — веб-чат для людей и HTTP API для разработчиков. Главное различие между каналами: Web хранит историю диалога на сервере, а API stateless — клиент каждый раз присылает полный контекст. Поэтому нагрузку нельзя усреднять по DAU, её нужно считать раздельно. Ключевой сценарий один: запрос приходит на edge, контекст уходит на GPU, ответ генерируется токен за токеном и возвращается клиенту через SSE.

## 0:30-1:05 — Слайд 2. Ключевой сценарий
Здесь видно главное различие между каналами. В Web-ветке пользователь отправляет сообщение через chat.llm.com, chat проверяет cookie в Redis, читает метаданные диалога и сообщения из PostgreSQL и ScyllaDB, после чего backend сам собирает полный context для GPU. В API-ветке клиент уже присылает полный context в JSON payload. api-gateway проверяет API token, rate-limit и billing credit, но историю сообщений не хранит. Дальше обе ветки одинаковые: regional-inference идёт в scheduler, scheduler выбирает GPU-worker, а токены возвращаются клиенту через SSE.

## 1:05-1:40 — Слайд 3. Нагрузка
Web и API считаются отдельно. Web — массовая аудитория живых пользователей, около 2.5 млрд сообщений в день. API — меньше клиентов, но они присылают полный контекст, поэтому дают примерно 78 тысяч peak inference RPS против 58 тысяч у Web. Из этого получаются три сильных ограничения: 136 тысяч inference-запросов в пике, 1.2 млн одновременных SSE-соединений и 129 ПБ данных в год. Поэтому узкое место не одно: одновременно нужны edge, GPU и отдельная стратегия хранения вложений.

## 1:40-2:15 — Слайд 4. Глобальная балансировка
Глобальная балансировка здесь — это выбор дата-центра. Я использую Anycast: домены chat, api и attach резолвятся в один общий IP, а BGP направляет пакет в ближайший живой ДЦ. Всего четыре ДЦ: US East, US West, EU и APAC. Они принимают HTTP и SSE локально, но GPU-кластеры размещены только в США: основной в US East и резервный в US West. Компромисс в том, что крупные GPU-пулы дают высокую утилизацию и меньшую стоимость на токен, а failover целого региона закрывается снятием BGP-анонса за 30-90 секунд.

## 2:15-3:00 — Слайд 5. Hot path inference
Запрос приходит на edge, дальше в api-gateway или chat, затем в regional-inference и scheduler. Scheduler делает только control plane: выбирает GPU-worker и возвращает endpoint. Токены через scheduler не идут: regional-inference открывает gRPC server-streaming прямо к GPU-worker, а обратно токены возвращаются через ingress как SSE. Внутри GPU-worker используется continuous batching и PagedAttention: batch пересобирается на каждом decode-step, KV-cache отдаётся блоками, а завершённые запросы сразу освобождают память. Это снижает простой GPU и позволяет держать нужный RPS меньшим парком H100.

## 3:00-3:40 — Слайд 6. Данные
Одна база данных здесь не подходит, потому что паттерны нагрузки несовместимы. PostgreSQL и Citus держат пользователей, разговоры, API-ключи и billing, потому что там важны транзакции и строгая консистентность. ScyllaDB хранит messages: нужен быстрый single-partition read по conv_id на петабайтном объёме. Redis обслуживает горячий путь — sessions, api-key cache, rate limits и короткий billing credit. ClickHouse пишет append-only usage_records для аналитики и биллинговых отчётов. Ceph RGW закрывает самый тяжёлый слой — вложения, примерно 126 ПБ в год.

## 3:40-4:25 — Слайд 7. Надёжность
Надёжность описана через конкретные failure modes. Для отказа ДЦ работает Anycast withdraw; для edge-слоя — 2N at 50%; для PostgreSQL — sync replica и Patroni promote; для Scylla — LOCAL_QUORUM при RF=3 в каждом ДЦ. GPU-слой держится двумя US-регионами: если падает один, второй принимает inference. Важно честно назвать предел: если одновременно недоступны оба US GPU-региона, новые inference-запросы возвращают 503. Это осознанный компромисс MVP, потому что полноценная GPU и PostgreSQL primary-площадка вне США резко увеличила бы стоимость.

## 4:25-5:00 — Слайд 8. Итог
Закрываю спецификацией. Всего получается 2 763 сервера без внешнего CDN. Самые крупные пулы — 700 GPU-нод, 1 200 Ceph OSD-нод и 620 ScyllaDB-нод. Это не произвольные числа: 30 edge-нод появляются из 1.2 млн concurrent SSE и модели 2N, GPU-парк — из 136k peak inference RPS и оценки 430 inference RPS на 8xH100-ноду, Scylla и Ceph — из объёма данных и репликации. Главная идея: HTTP edge рядом с пользователем, дорогой inference централизован, а state размещён там, где это снижает latency или защищает деньги.
